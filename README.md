Drosak Plus - إصلاح التجربة مرة واحدة والتحقق من كود الجروب

الملفات:
- bot/server.js: ملف سيرفر البوت المعدل.
- bot/public/index.html: لوحة الأدمن الحالية.
- bot/package.json: package الخاص بخدمة البوت (لم يتغير).
- platform/server.js: ملف سيرفر المنصة المعدل.

التعديلات:
1) منع إصدار تجربة ثانية لنفس Telegram user ID باستخدام botTrialClaims/{telegramUserId} في Firebase، وهو سجل دائم مستقل عن وجود كود الطالب.
2) إذا انقطع إصدار التجربة بعد حفظ الكود، يحاول السيرفر استرجاع نفس الكود بدل إصدار كود جديد.
3) لو الطالب كان مربوط بكود تجربة قديم، يقدر يربط كود اشتراك فعّال جديد بنفس حساب Telegram. ما زال يمنع ربط كود الطالب بحساب Telegram آخر.
4) البوت يوضح سبب رفض التحقق بدل رسالة عامة تقول إن الكود خطأ؛ ويدعم الأرقام العربية في الكود.

طريقة التحديث:
- خدمة البوت: استبدل server.js في مشروع البوت بهذا الملف bot/server.js. اترك package.json و public/index.html كما هما في المشروع، أو استخدم النسخ المرفقة.
- خدمة المنصة: استبدل ملف التشغيل الحالي فقط بالكود الموجود platform/server.js. احتفظ باسم ملف التشغيل الأصلي في مشروع المنصة (مثل server.js أو app.js)؛ لا تغيّر package.json الخاص بالمنصة ولا تستبدل package الخاص بها بpackage البوت.
- تأكد أن BOT_TRIAL_SECRET متطابق حرفيًا في خدمة البوت وخدمة المنصة.
- تأكد أن PLATFORM_API_URL في خدمة البوت هو عنوان خدمة المنصة من الجذر، بدون /api في آخره.
- SUBSCRIBERS_GROUP_ID لخدمة البوت: -1006048441567
- تأكد أن Firebase Realtime Database متصل بخدمة المنصة وأن قواعدها تسمح للسيرفر باستخدام FIREBASE_SECRET.
- بعد تحديث الخدمتين، اعمل Deploy لكل خدمة.

تنبيه:
فحص Node syntax تم للملفين. لم يتم إجراء اتصال مباشر بقاعدة Firebase أو اختبار Telegram/Railway الحقيقيين من هنا. لا تحذف botTrialClaims من Firebase، لأنه سجل منع تكرار التجربة.
